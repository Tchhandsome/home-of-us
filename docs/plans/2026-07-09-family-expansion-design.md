# Home Of Us 剩余功能扩展设计

## 1. 目标与范围

这一轮只实现用户已经确认的剩余需求 `6 / 8 / 9 / 10`，并坚持“先能稳定上线，再逐步增强”的原则，不引入 AI 解析、营养算法、复杂推荐或多级审批流。整体思路是尽量复用现有领域模型：把“记录”替换为共享待办，把“共同相册”升级成时刻墙，把“库存”扩展为库存提醒与食品过期提醒，再新增“家庭投票”和“菜谱餐单”两个轻量模块。首页继续维持唯一入口，所有模块仍旧通过卡片进入，排序偏好继续保存在后端个人偏好里；原先的 `album` 卡片在 UI 上改名为“时刻墙”，原先的 `record` 卡片改名为“待办”，并补上 `inventory`、`recipes` 等模块卡片。所有新页面继续遵循前一轮已经确认的交互模式：默认先看列表，点 `+` 进入新增页，编辑也走独立页，不再出现“上半区表单、下半区列表”的堆叠式界面。

## 2. 领域建模方案

共享待办直接基于现有 `chore_task` 扩展，而不是再造一张新表。新增 `task_scope`、`owner_member_id` 等字段后，它就可以同时承载“个人任务”和“家庭公用任务”；`assignee_id` 继续表示认领人，`status` 继续表示待办/完成，前端通过“全部 / 我的 / 共享 / 已完成”过滤即可满足用户场景。时刻墙则复用现有 `album_photo`，将其升级为通用记忆条目：增加 `entry_type`、`wish_text`、`reminder_enabled`、`reminder_days_before`、`next_remind_at` 等字段，让一条记录既可以是照片，也可以是文字心情、纪念日、生日。这样能最大化复用现有上传、删除、排序和提醒联动能力。库存模块扩展现有 `inventory_item`，增加 `item_type`、`expires_on`、`reminder_days_before`、`note` 等字段，用于区分消耗品与食品；低库存提醒和过期提醒都通过 `reminder` 统一生成与回收。投票与菜谱由于现有模型中没有合适承载体，新增轻量表最合适：投票采用 `family_vote / family_vote_option / family_vote_choice`，菜谱采用 `recipe / meal_plan` 两张主表，并把原料先存为结构化文本或 JSON 字符串，避免第一版就把原料维度拆得过细。

## 3. 页面与交互设计

待办页替换现在的“记录页”，默认进入全部任务列表，顶部有筛选条和 `+` 按钮。新增任务时可以选择“个人任务”或“家庭公用任务”，共享任务允许无人认领，后续其他成员可以点“认领”；已认领任务在公共列表中显示认领人，在“我的任务”中过滤出来。时刻墙沿用现有 `album` 页签，但页面语义改成“时刻墙”：默认是时间线列表，上方只保留标题和 `+`，新增页里先选记录类型，再按类型展示字段；纪念日和生日记录可以设置提醒天数与愿望清单。库存页做成两个分段：“物资”与“投票”。物资页显示库存状态、低库存/临期标记和删除入口；投票页显示当前开放投票与历史投票，支持默认模板“一起吃什么”“一起玩什么”，一键注入默认选项，再支持“随机选一个”并封存结果。菜谱页同样采用列表优先：先看菜谱库，进入某周餐单页后可手动选菜或一键生成本周餐单；生成后可以选择为餐单自动创建提醒，也可以一键把原料合并到购物清单。为了减少页面复杂度，投票功能放在库存页中，时刻墙功能放在原相册页中，避免首页卡片无限膨胀。

## 4. 提醒、同步与校验策略

这一轮新增的自动化都走后端规则而不是前端临时拼装。共享待办如果设置了截止时间，就生成来源为 `TODO_TASK` 的提醒；纪念日/生日记录根据 `taken_on` 与提醒天数计算下一次触发时间，创建 `MEMORY_EVENT` 提醒；库存项若低于阈值则生成 `INVENTORY_LOW` 提醒，若设置了 `expires_on` 则生成 `INVENTORY_EXPIRE` 提醒；餐单计划若设置提醒则生成 `MEAL_PLAN` 提醒。所有提醒在对应业务对象更新或删除时，都通过 `source_type + source_id` 回收并重建，保持幂等。跨设备同步继续依赖现有轮询和聚合接口，不再额外引入 WebSocket。测试上，后端优先补 `ChoreService`、`AlbumService`、`InventoryService` 以及新建投票/菜谱服务的单元测试，确保提醒联动、删除回收、个人权限和默认规则可控；前端至少完成 `npm run build --workspace apps/mobile` 构建校验，并在本地启动移动端页面做手工验收。最后一个动作是关闭本轮启动过的开发服务，避免留下悬挂进程。
